## 容量基准和场景定义

令 D_C、D_M 分别是所选轨迹在 5 分钟窗口中的 CPU 和内存总请求量。对每个维度取 P95 作为主体规模参考，P99 和峰值用于压力校核。历史请求曲线来自历史实际运行区间，实际使用曲线来自采样；两者都与提交即运行、重新调度的负载曲线具有不同含义。

| 样本口径 | 分位 | CPU 请求 | 内存请求 | CPU 实际使用 | 内存实际使用 | 窗口峰值并发 |
|---|---|---:|---:|---:|---:|---:|
| 历史观测 | P95 | 7,538.308 | 5,970.185 | 4,326.543 | 3,091.973 | 146,478.000 |
| 历史观测 | P99 | 7,651.914 | 6,322.446 | 4,688.429 | 3,187.618 | 153,725.500 |
| 历史观测 | MAX | 7,808.411 | 8,666.299 | 5,013.440 | 3,326.514 | 171,231.000 |
| 严格批任务代理 | P95 | 2.319 | 1.460 | 0.427 | 0.247 | 68.000 |
| 严格批任务代理 | P99 | 2.724 | 1.770 | 0.593 | 0.343 | 79.000 |
| 严格批任务代理 | MAX | 3.402 | 2.466 | 1.059 | 1.127 | 108.000 |

本次容量建议基于任务事件 696.00 小时与用量 696.00 小时的实测窗口。未达到全轨迹时，窗口内分位数用于设置预实验参数，后续应重估代表性。

场景容量使用请求和用量共同覆盖的 5 分钟窗取 P95。

下表暂用**严格批任务代理**的 P95 请求总量，工作负载倍率 α=1。每个目标负载率 ρ 定义为参考需求除以容量，CPU 和内存各自按 C=α·P95(D)/ρ 计算。这些是容量场景的设计比例。仿真 CPU 利用率需按实际运行时的有效使用量另行测量。

| 目标负载率 | 归一化 CPU 容量 | 归一化内存容量 | 参考机器等效数下界 |
|---:|---:|---:|---:|
| 45% | 5.153 | 3.244 | 11 |
| 65% | 3.568 | 2.246 | 8 |
| 85% | 2.728 | 1.718 | 6 |

参考机器是 t=600 秒样本中最常见的容量对（0.5, 0.4995）。机器等效数是两个维度的总量下界，实际装箱还要满足同一台 Host 可容纳完整 VM。

将 256 台同规格参考机器作为容量情景，当前口径的 P95 负载占其归一化 CPU 容量 1.81%、内存容量 1.14%。该比值用于判断应验证怎样的负载规模。新 Host 规格确定后可代入实配容量重新计算。

设 CPU 校准系数 K_C 为每个归一化 CPU 单位对应的研究参考核数，K_M 为每个归一化内存单位对应的 GiB。绝对容量下界为 ceil(C_C·K_C) 核和 ceil(C_M·K_M) GiB。两个缩放常数独立，Google 轨迹公开值不足以反推出本研究现代服务器的核心、MIPS、物理内存或功率。配置 Host 时还要单独提供可用 CPU 份额、可分配内存、基准算力和空闲／满载功率。

### 异构服务器与缩放

分别比较同规模的单规格、CPU 偏重加内存偏重两规格，以及第三种高能效通用机型。用相同 Cloudlet 需求和时间窗对各组合做二维 VM 装箱，比较放置成功率、资源碎片、留出容量及功率曲线。如果第三种规格没有提高可行性或降低实测能耗，优先保留两种规格。P95 或 P99 的分维下界应再用同一时段的成对 CPU／内存需求和峰值验证。

将原轨迹用于单数据中心场景时，优先抽取连续的一天或多天稳定窗口，然后对 Job ID 做固定种子、分层的整组抽样，保留相对到达时间、任务请求和持续时间。按日、时段、任务类别、CPU／内存联合档位复验抽样后分布与峰均比。减少 Job 数量后重新统计负载，不把任务核心和内存按比例直接压小，也不把主机规模按全轨迹记录数线性外推。

## VM 规格与按需回收

对严格批任务代理的双维请求先拟合三档候选包络。每档从 CPU 和内存的边际分位值取得初始容量，再用联合分布核验命中率，任何任务都必须在同一规格内同时满足两个维度。

严格批任务代理在共同观测窗口中的 5 分钟峰值并发为 P95 68、P99 79、最大 108。若以一台 VM 同时运行一个任务为对照，这也是对应的活跃 VM 需求，启动中与延迟回收的 VM 另计。生产配置还应叠加规格装箱、回收滞后和仿真基准的压力校验。同一口径下，观测峰值活跃数为 1,536 台候选池的 7.03%。

| 候选包络 | CPU 请求上界（归一化） | 内存请求上界（归一化） |
|---|---:|---:|
| P50 初始包络 | 0.024990 | 0.012440 |
| P90 初始包络 | 0.062500 | 0.031800 |
| P99 初始包络 | 0.062500 | 0.098630 |

逐任务双维核验显示，P50 档覆盖 33.8%，P90 档覆盖 90.2%，P99 档覆盖 98.5%。

CPU 不高于中位数且内存不低于 P90 的任务有 2,059 个（占双维请求均可用的严格批任务代理 2.36%）。

用校准系数转换时，将 CPU 向上取整为支持的 vCPU 档位，内存向上取整到可采购或仿真的规格。用每个任务的双维请求选择可行 VM 中预计新增容量最小的规格。CPU 小且内存大的任务可分到内存偏重规格；是否单独开一档由覆盖率、装箱损失和能耗结果决定。超大任务可进入显式的大规格或不可行队列，保留分类和计数，禁止静默截断需求。

VM 池只统计已创建／启动中／占用／等待回收的实例。按到达的 Cloudlet 先查找满足资源和截止时间的现有 VM，其次决定是否启动新 VM。策略应包含启动耗时、回收阈值与最小驻留时间。允许独立任务共用 VM 时，同步检查并发所需核心和内存之和，队列需按期限或策略运行。VM 数量由实际峰值并发、分规格装箱、启动等待和 SLA 决定，需用回放测量。

外部校准仍需现代服务器规格与实测功率、每核性能基准、VM 启动及回收时延、内存保留口径、目标 SLA 及碳强度时序。校准后再评估任何固定服务器或 VM 数量。
