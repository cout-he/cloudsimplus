# V1.2 多规格 VM 与完整工作负载基准仿真

从 V1.1 提交 `ed8a8e72c555ce17b6e63064a752aa2db64a1db9` 扩展。实验入口位于 Maven 测试源码，读取同一份 [基准配置](baseline.properties)、[九种 VM 规格](vm-specs.csv) 和已提交的三套 [V1.1 工作负载](../synthetic-v1/results/)。主机来自 V1.0 的 `CarbonHostFactory`。最终结果和完整核对见 [验证报告](reports/validation.md)。

## 调度与资源

- **任务到达。** Broker 在任务到达事件后才准入，按到达时刻和 ID 保持严格 FCFS。首先按 VM 创建顺序寻找 CPU 与 RAM 都有剩余的现有 VM，排除启动中和回收中的实例。
- **按需创建。** 预检要求每项规格至少能放进一台 Host，每条任务至少能匹配一项规格。可承载的规格按剩余核数、剩余 RAM 和配置顺序排序。对第一个可放置的规格，从原始 Host 列表的开头扫描。A 类位于 B 类之前，这一基线有顺序偏好。资源不足时队首保持等待，在任务完成或 VM 释放 Host 资源后重试。
- **性能绑定。** 先选 Host，再用它的每核 MIPS 创建 VM。实验层的 `VmPlacementPolicyFirstFit` 适配器把选中的 Host 交回 CloudSim，复用原生放置与释放。创建 ACK 后才提交绑定的 Cloudlet，每核 MI 直接传给 `CloudletSimple`。单个任务占用多个核，总工作量为核心数乘每核 MI。
- **任务级内存。** Broker 从准入到任务返回预留 CPU 和 RAM。VM 内使用原生空间共享调度。任务内存需求在实验层计账，Cloudlet RAM 利用率保持默认，避免重复记入。时间序列分别记录正在执行任务的 RAM 和 Host 分给 VM 的 RAM，两个指标使用同一物理容量作为分母。
- **生命周期。** 初始 VM 池为空。空闲计时在最后一项预留释放后开始，任何复用都会使旧计时失效。默认空闲 1,800 秒后调用 VM 原生销毁，Host 释放的实际事件会触发下一轮准入。启动延迟用实验层的就绪事件实现，VM 从实际放置到可准入之间占用 Host 资源并保持空闲功率。当前框架在事件驱动模式下的原生正启动延迟会连续调度零时间更新，就绪事件避开了这一循环。销毁延迟走原生 VM 关闭事件。
- **失败。** 没有可用的当前放置时，任务保留在 FCFS 队列。原生创建失败有独立计数，候选组合会在资源改变前排除。没有活动 VM 能释放资源且候选已耗尽的任务记录为明确的终态。进度检测会显式报告异常停滞。

用长度为 120,000 MI/核的 4 核任务验证。在 A、B 类 VM 上的预期执行时间分别为 38.822 秒和 60 秒，Maven 测试按原生执行记录核对。

每次准入最坏扫描当前 VM 池，再扫描固定数量的规格和 Host。调度仅在到达、VM 就绪或资源释放等事件触发。每次执行状态变化只更新一台 Host 和全局累加器，额外的积分开销为 O(1)。队列、生命周期及输出记录的存储规模随场景任务数和 VM 数增长。

## 能耗与截止时间

112 台服务器保持开机，空闲 Host 按 V1.0 的 SPECpower 空闲功率计入。运行中的 CPU MIPS 来自 Cloudlet 的实际开始、完成和原生分配的 VM 每核 MIPS。每次负载变化更新对应 Host 的功率，并对变化之间的区间积分，使用 `W × 秒 ÷ 3,600,000` 得到 kWh。采样每 60 秒一次，另记录 24 小时边界和清空结束，采样精度与积分精度独立。

提交窗口为 `[0, 86400)`，该窗口的 CPU 和 RAM 指标是时间加权平均。窗口之后继续执行已经到达的任务，清空能耗统计到最后一个任务终态。后续仅用于 VM 回收的时间单独体现在模拟器结束时刻中。功率统计边界为服务器 IT。开展碳排放与低碳调度比较还需要与实验时钟对齐的电网碳强度序列、公开的碳强度口径和一致的清空阶段核算方法。

截止时间来自 V1.1 CSV，完成时刻不晚于截止时刻算按时。Deadline 仅用于评价。截止违约率以成功完成数为分母，另有以全部输入为分母且包含其他终态的 SLA 失败率。等待时间从到达到开始，执行时间由 CloudSim 给出，周转时间从到达到完成。P95 使用最近秩，超期时长只对超期完成任务统计。
